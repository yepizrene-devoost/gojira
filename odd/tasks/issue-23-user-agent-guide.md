# Issue 23 — optional per-user agent guide
Optional guide an agent can read, installed only on explicit request, never as a tracked file.
Implementation authorized; leave changes unstaged and uncommitted for user review.
Standing rule from the user: strict TDD and strict SOLID, always.

## Specs

- S1: "si dale con la guia strict tdd y strict solid siempre". Strict TDD means: for every behavior, a failing test is observed first (exact command, exit code and failure reason recorded) and only then the implementation; no test is written after its implementation. Strict SOLID means: one responsibility per file and type, consumer-defined small interfaces, injected dependencies (filesystem, Git), no speculative abstraction, no growth of existing large files.
- S2: Issue #23 item 4, verbatim: "Optional agent guide, per user — if wanted, installed at user level (for example the user's agent skills directory) or repo-local but untracked via `.git/info/exclude`. Never a tracked file and never an `AGENTS.md` edit." Earlier design: "Default: install nothing. MCP instructions/resource is the repo-free route. A later explicit guide-install command may target a user-selected per-user skill location, or a repo-local file excluded using .git/info/exclude. Preview changes, never overwrite without consent, never edit AGENTS.md. Client-specific skill formats remain adapters, not a required Gojira runtime dependency."
- S3: Nothing is installed by default and no existing command changes behavior. The guide is only produced by new commands.
- S4: The guide text never contains secrets, tokens, emails or personal data, and states that ticket text is untrusted data.
