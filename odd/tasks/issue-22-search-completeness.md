# Issue #22 — make `gojira search` complete or explicitly truncated

Agents asking for "all my tickets" got at most 50 (default) or 100 results with no signal. On the user's real Jira the query returned 50 of 696 tickets. GitHub source of truth: [issue #22](https://github.com/yepizrene-devoost/gojira/issues/22). Chosen contract (L5): keep default limit 50, paginate for real, warn on truncation, add `--all` and `--meta`.

## Specs

- S1: Add `Client.SearchIssues(jql string, limit int)` returning a result with `Issues []Issue`, `Truncated bool` and `EstimatedTotal *int`. It paginates `GET /rest/api/3/search/jql` with `nextPageToken` (verified L3): request `maxResults=min(100, remaining)`, follow the token until `limit` issues are collected or Jira reports `isLast`/no token. Jira caps pages at 100 even if more is requested. `Truncated` is true only when more results exist after reaching `limit`. Guard against token loops with a documented maximum page count. `limit <= 0` means the default 50.
- S2: Estimated total: only when `Truncated`, make ONE `POST /rest/api/3/search/approximate-count` with body `{"jql": <the same jql>}` (path constant in `internal/jira/paths.go`) and parse `count`. It is best-effort: any failure leaves `EstimatedTotal` nil and never fails the search. It is documented as an estimate and requires bounded JQL; if Jira rejects the JQL for counting, omit it.
- S3: CLI `gojira search <jql>`: default limit 50 and default stdout unchanged (bare TicketJSON v1 array). New `--all` fetches everything up to a documented safety cap of 10,000 issues (if the cap is hit, `truncated` is true). `--all` together with an explicit `--limit` is a `validation_error` (not_applied) with zero requests. `--limit <= 0` keeps today's meaning (default 50).
- S4: Truncation signal. When the result is truncated and `--meta` is not used: exit code 0, stdout unchanged, and in JSON mode write ONE JSON warning object to stderr `{"schemaVersion":"v1","code":"results_truncated","returned":N,"estimatedTotal":E,"hint":"..."}` (omit `estimatedTotal` when unknown; the hint is English and tells the agent to rerun with `--all` or a larger `--limit`, or narrow the JQL, and not to report the list as complete). In human mode print a plain `Warning:` line to stderr. Stderr carries nothing when the result is complete.
- S5: `--meta` (implies JSON output) writes one object to stdout: `{"schemaVersion":"v1","issues":[TicketJSON...],"returned":N,"truncated":bool,"estimatedTotal":E}` (`estimatedTotal` omitted when unknown). No stderr warning in this mode. `issues` is `[]`, never null, when empty. The default array shape and every existing field stay unchanged.
- S6: Human table output: remove the fabricated total (`total = shown` fallback) and the invented `... and N more` count. Print `Showing N issues` and, only when truncated, a line saying more results exist (with `about E in total` only when known).
- S7: `Client.SearchJQL` and `Client.SearchText` keep their current signatures and call sites (`internal/tui/tui.go` uses `SearchText(query, 50)`): they become thin wrappers over `SearchIssues`, return `total = 0` as today (unknown), and keep working for limits above 100 by paginating. No TUI change in this unit.
- S8: Errors reuse `commandError` and the I20-7 classification; invalid JQL, 401/403/404 and 5xx behave as today. Endpoints only in `internal/jira/paths.go`. Diagnostics on stderr, valid JSON on stdout.
- S9: README: document the limits (Jira pages cap at 100; default 50; `--all` safety cap), `--all`, `--meta`, the stderr warning shape, that the total is an estimate, and that the old `/rest/api/3/search` is being removed. Do not claim more than L3 verified.
- S10: Tests (RED first, httptest only): token pagination across pages; limit not a multiple of 100; limit equal to the total is NOT truncated; first page `isLast` true; token-loop guard; `maxResults` never above 100; approximate-count success, failure and nil estimate; CLI default stdout unchanged for a complete small result (no stderr); truncated default prints the stderr warning and exits 0; `--all` collects everything and hits the cap; `--all` with `--limit` is `validation_error` with zero requests; `--meta` shape (including empty `issues: []`); human output has no fabricated total; wrappers keep TUI behavior; 4xx/5xx and invalid JQL unchanged. `go vet`, `go test ./... -count=1`, `golangci-lint run ./...` green; new tests race-clean.
