- S3: Four opt-in write tools, registered only with `--allow-writes` (read-only default registers none): `gojira_sprint_move` (`key`, `sprintId` positive integer), `gojira_backlog` (`key`), `gojira_close` (`key`), `gojira_reopen` (`key`). Same Jira calls as the CLI: `AddIssuesToSprint(sprintId, [key])`, `MoveIssueToBacklog(key)` and a single `TransitionIssue`. Same envelope and mutation states (`applied`, `not_applied`, `unknown`), no automatic retry, hints unchanged, key validated like the other write tools, and every rejected input leaves Jira untouched (zero mutation calls).
- S4: `gojira_close` and `gojira_reopen` pick the transition exactly like `gojira close` / `gojira reopen`: exactly one available transition whose destination status category is `done` (close) or `new`/`indeterminate` (reopen); zero or several candidates are a `validation_error` with `mutationState: not_applied`, no mutation, and a message listing the candidates so the agent can use `gojira_move` with an exact status name. The selection rule lives in ONE shared package consumed by the CLI and the MCP adapter (no duplicated rule); CLI messages, exit codes, JSON and requests stay byte-identical to the previous behavior.
- S5: Strict TDD and strict SOLID (standing preference). Per rule one observed behavioral RED, then GREEN; tests assert requests/payloads, result fields and zero mutation on rejection; one regression test per touched existing behavior; the existing `TestLifecycleCLI`, sprint and backlog tests stay unmodified and passing; the existing write-enabled surface test is extended additively, never weakened. Parent differential of the CLI against the base commit. No live Jira, keychain or `.env`.
- S6: Docs ship with the behavior: README MCP tool table and the capability matrix `docs/interface-parity.md` move the affected rows. Work stays unstaged and uncommitted for maintainer review (AGENTS.md).
- S7: Out of scope: the TUI (`internal/tui/tui.go` keeps its own category selection; deduplicating it is a recorded follow-up), create-in-sprint and create-under-parent (those belong with #24), MCP assign by email, export, JQL search in the TUI, and any change of existing tool contracts.
